# MyGo PDF design

MyGo PDF is a read-only PDF viewer for desktop applications. It supports continuous vertical scrolling, zoom, fit-to-width and fit-to-page, text selection and copying, and links. The host can build its own controls using the public API. See the [development plan](plan.md) for milestones and release criteria.

## Packages

| Location | Responsibility |
| --- | --- |
| [Root `pdf` package](../api.go) | Public API, UI-thread state, MyGo view and input, viewport layout, bitmap caching, and worker scheduling |
| [`internal/pdfium`](../internal/pdfium) | PDFium loading, platform ABI, native handles, rasterization, and text and link extraction |
| [`internal/render`](../internal/render) | Raster request keys, size limits, and cache budgets shared by the viewer and PDFium layers |
| [`cmd/pdfium-resources`](../cmd/pdfium-resources) | Verify upstream archives and libraries, and prepare the library and licenses for the host's build |
| [`examples/viewer`](../examples/viewer) | Demonstrate host-side file opening, toolbar composition, and embedded preview |

The root package depends on `internal/pdfium` and `internal/render`. The PDFium package uses `internal/render` and has no MyGo dependency. The host owns file opening, path authorization, monitoring, document generation, persistence, and export.

## Public contracts

- `NewViewer` binds to one MyGo window and tracks its display scale and lifetime. Call the API on the window's UI thread and build the view with a stable `c.Key`. Change the comparable layout argument to `View` when the parent layout changes.
- `LoadBytes` takes ownership of immutable bytes and accepts a cancellation context. It returns the request generation. Opening a new document clears the current document and starts on the first page. Refreshing keeps the existing image, zoom, and reading position until the new visible pages can be installed together. A previously measured viewer applies a successful refresh once its view is built with current geometry. If the host temporarily hides that view, the refresh can be canceled or can finish when the view returns.
- `LoadReaderAt` borrows a local `io.ReaderAt` and size. The host keeps the source stable and readable until its release channel closes, then closes the file as needed. The successful load's context can end while the document is displayed. A failed refresh releases its candidate and retains the displayed source. Native closure precedes release for each installed reader. `LoadBytesWithOptions` and `LoadReaderAt` take an optional password. `State.Err` reports `ErrPassword` when the password is missing or wrong. Hosts provide retries as new requests.
- `State` returns a snapshot. `OnChange` coalesces notifications and invokes callbacks on the UI thread after committing state. Callbacks may clear, close, or start another load. Public page numbers start at 1, with 0 for an empty document. Opening a document or explicitly navigating to a page selects that page even if multiple pages fit in the viewport. Once the vertical scroll offset changes, the current page follows the viewport center or the nearest page when the center falls in a gap.
- `ReadOutline` returns a bounded snapshot asynchronously on the window thread. `GoToOutline` accepts a local target from the same viewer and displayed generation. `Find` requests one match, wraps at the document boundary, and reports its result in `State.Find`. New loads cancel pending outline and find work. Both use the displayed document generation to discard stale results. Deferred page and outline navigation failures appear in `State.Err`. When a search target cannot be measured, the find state reports the error and clears the active match. Search exposes positions through navigation and highlighting and keeps ordinary copying subject to the document's permission.
- `SetRotation` applies clockwise quarter turns relative to each page's intrinsic orientation. Opening resets the view rotation and refreshing preserves it. Raster keys carry the rotation. Selection, links, destinations, and find boxes use a shared transform from canonical page coordinates. Existing page previews rotate during refinement.
- `Close` returns immediately and stops accepting results. `Done` closes when the worker releases the native document. Wait off the UI thread. Menu labels default to English and can be overridden or supplied by `ChineseLabels`. The viewer handles internal destinations and passes validated `http`, `https`, and `mailto` URLs to the host's `OnLink`. Hosts that supply `OpenExternal` can use `CanOpenExternal` to decide whether to show that menu item for the current document.

## Rendering and resources

PDFium calls are serialized within the process. Document bytes stay pinned until the native document closes. A reader-backed document uses one purego trampoline for process-wide file access. PDFium reads into a temporary native buffer using a registered source token, with read errors scoped to each operation. The worker coalesces viewport requests and uses `Window.Update` to apply results that still match the current document generation and raster demand. Progressive rendering yields at PDFium pause points and checks for cancellation before resuming. Visible work has priority over prefetch across windows. A canceled prefetch waiting to resume joins the foreground queue in arrival order to release its native resources. At most four native rasters are active, with one slot reserved for visible work. A native call must return before its resources can be released. An explicit library override with missing progressive symbols uses synchronous rendering.

The viewer builds only visible pages and reuses page geometry across viewport and zoom changes. For bytes, it measures all dimensions before opening. For readers, it measures the opening viewport first and estimates the remaining dimensions. A segment tree tracks page extents and fit maxima. Interactive dimension requests take priority over the background scan, and size updates retain the reading anchor. Every page raster uses exact dimensions. It queues missing visible-page bitmaps, visible text and link geometry, visible image refinements, and one preview in the scroll direction, in that order. The neighboring page gets its dimensions and preview before the remaining background scan. It displays existing bitmaps during zoom and retains nearby tiles within one tile of the viewport. A retained tile is drawn only when its raster key matches the current scale and viewport demand. Whole-page bitmaps, tiles, and text and link geometry have separate budgets of 24 MiB, 40 MiB, and 8 MiB. `State.Render` describes the visible bitmaps. Text and links become interactive when their geometry is available for the displayed page. Document bytes, in-flight bitmaps, and native memory are accounted for separately. One document can contain up to 256 MiB of input and 100,000 pages.

Internal links support `XYZ`, `Fit`, `FitH`, `FitV`, `FitR`, `FitB`, `FitBH`, and `FitBV`. Destination zoom is subject to the viewer's zoom limits. Bounding-box modes estimate content extent from page objects within the crop box, with the cropped page as the fallback for empty pages or unavailable bounds. PDFium exposes a numeric coordinate for an explicit null `FitH` or `FitV` parameter. The viewer treats that value as coordinate zero. For `XYZ`, PDFium exposes which axes and zoom are present. The viewer preserves the in-page relative position or scale for omitted values and keeps the target page in view.

Visible pages have a group named for their page number, up to 8 KiB of accessible text per page when permitted, and focusable links with labels and activation actions. Semantics share the visible-page geometry and metadata cache. Keyboard and assistive activation follow the same routing as pointer activation. Text extraction uses PDFium's order and permission flags.

Build targets are macOS 13 or later, Windows, and glibc Linux on amd64 and arm64. `mygo-plugin.json` declares the matching PDFium library and a shared file with all license notices. MyGo fetches and verifies both assets during development and packaging, and places them at the root of the app's resource directory. At runtime the viewer loads the bundled library without network access. An absolute `LibraryPath` override supports custom packaging. Track build coverage, PDFium integration tests, native input, and installer verification separately for each platform.
